# CD Store — النسخة المبسطة v6

نسخة مرتبة لتكون سهلة جداً للمستخدم والأدمن، مع الحفاظ على الدفع والطلبات والدعم.

## واجهة المستخدم

- عند `/start` تظهر المنتجات مباشرة بعد رسالة الترحيب.
- المنتج المتوفر يظهر بزر أخضر.
- المنتج الذي مخزونه صفر يظهر بزر أحمر.
- أزرار الشحن والدفع تستخدم نمط Telegram الأزرق `primary`.
- اللغة العربية والإنجليزية موجودتان، ومحتوى المنتجات الذي يكتبه الأدمن بالعربي يترجم للإنجليزية تلقائياً.
- الإعلانات وردود الدعم المكتوبة بالعربي تترجم تلقائياً للمستخدم الذي اختار English.

## لوحة الأدمن

لوحة `/admin` تظهر فقط للأرقام الموجودة داخل `ADMIN_IDS`، وأمر `/admin` يضاف لقائمة أوامر Telegram للأدمن فقط.

أهم الأقسام:

- إضافة منتج.
- المنتجات وإدارتها.
- الطلبات ودفعات SuperQi.
- إدارة المستخدمين والرصيد.
- الدعم والإعلانات.
- الإحالات والقناة.
- إعدادات المتجر.
- زر `الإشعارات` داخل لوحة الأدمن: تشغيل/إيقاف الإشعارات التلقائية للمنتجات والمخزون.

## إضافة منتج

يوجد مكان واحد واضح: `➕ إضافة منتج`.

أول سؤال:

**ما نوع المنتج؟**

1. `كود`
2. `إيميل وباسورد`
3. `منتج حر`

بعدها يطلب فقط:

1. الاسم بالعربي.
2. السعر.
3. الوصف بالعربي.
4. الضمان بالعربي.
5. الصورة.
6. المخزون.

لا يطلب منك كتابة الإنجليزية؛ الاسم والوصف والضمان تترجم تلقائياً.

### المخزون

**كود** — كل كود بسطر:

```text
ABC-123
XYZ-456
```

**إيميل وباسورد** — كل حساب بسطر:

```text
email@example.com|password
```

**منتج حر** — كل سطر قطعة مستقلة، ويمكن أن يكون كتابة أو رابطاً أو بيانات أو أي نص:

```text
أي محتوى تريد تسليمه
```

## Telegram Premium Custom Emoji

إذا كتب الأدمن اسم المنتج وداخله Custom Emoji من Telegram Premium، يخزن البوت `custom_emoji_id` تلقائياً. ويمكن أيضاً كتابة ID الإيموجي بين أقواس مربعة مثل `[5221980268230882832] اسم المنتج`؛ الأقواس والرقم لا يظهران للزبون، وإنما يستخدم الـID كـCustom Emoji. إذا لم يسمح Telegram باستخدام الـCustom Emoji يوجد fallback حتى لا تتعطل قائمة المنتجات.

تمت إضافة قاموس مركزي ثنائي اللغة لكل معرفات الإيموجي التي زود بها المالك البوت. لذلك:

- أسماء مثل `كانفا / Canva` و`تيليجرام / Telegram` و`نتفلكس / Netflix` تُربط بالإيموجي تلقائياً في المنتجات والخدمات والأزرار.
- المنتجات القديمة تستفيد من المطابقة وقت العرض حتى إذا أُنشئت قبل إضافة القاموس.
- عند بدء البوت، تُصحّح تلقائياً معرّفات المنصات المعروفة المحفوظة خطأ داخل بيانات المنتج، مع تغيير حقول الإيموجي الثلاثة فقط والإبقاء على الوصف والمخزون والمبيعات وكل الحقول الأخرى.
- القاموس المدمج هو قيمة افتراضية فقط. إذا حفظ المالك ربطاً جديداً لنفس الخدمة، يصبح ربطه المخصص هو الأعلى أولوية. أما كلمة عامة مثل `مشترك` أو `جوجل` فلا تتغلب على خدمة أدق مثل `كاب كات` أو `جيميل` داخل اسم مركب.
- كل منتج يظهر في زر واحد كامل. لأن Telegram يسمح بإيموجي مميز واحد فقط داخل الزر، تُحجز هذه الخانة لإيموجي المنتج أو الخدمة، بينما يظهر إيموجيا المال `5361656830944624968` والصندوق `5366201992970518798` داخل رسالة تفاصيل المنتج التي تدعم عدة إيموجيات مميزة.
- رموز الوردة والهاتف القديمة تُنظف من اسم المنتج عند العرض فقط، ولا يُحذف أو يتغير اسم المنتج أو مخزونه في قاعدة البيانات.
- تهجئات Gemini العربية `جمني` و`جيميني` و`جمناي` و`جيمناي` مدعومة. وبما أنه لم يُرسل معرّف مستقل لـGemini، تستخدم حالياً معرّف Google المرسل من المالك.
- تهجئة Canva الناقصة `انفا` مدعومة أيضاً لتصحيح المنتجات الموجودة بهذه الكتابة.
- عند إضافة أو تعديل منتج، يُحفظ معرف الإيموجي داخل بيانات المنتج مع الإبقاء على جميع حقوله القديمة.
- رموز الإجراءات التي زود بها المالك، مثل النجاح والخطأ والبحث والحذف والتعديل والإعدادات، تُطبّق على أزرار البوت ورسائل HTML المدعومة.
- الرموز العادية تُحذف مركزياً من الرسائل والأزرار؛ تُستخدم الإيموجيات المميزة المتاحة فقط. تبقى الرموز العادية الضرورية للتنقل أو للتحذير والخطر عندما لا يوجد بديل مميز صالح.
- إذا رفض Telegram الإيموجي المميز في زر أو رسالة، يعيد البوت الإرسال بلا الرمز بدلاً من تحويله إلى إيموجي عادي، حتى لا تتوقف العملية.

لإضافة ربط جديد: `/admin` ← **إعدادات المتجر** ← **الإيموجيات المميزة**. هذا القسم يظهر للمالك الرئيسي فقط. اكتب المعنى بالعربية؛ البوت ينشئ الاسم الإنجليزي تلقائياً، ثم أرسل الإيموجي المميز أو رقمه بين أقواس مربعة. الربط محفوظ في قاعدة البيانات ويعمل على اللغتين.

### البحث عن أي نص أو زر وتعديله — v7.2

من `/admin` ← **إعدادات المتجر** ← **الإيموجيات المميزة** ← **البحث عن نص أو زر**:

- اكتب جزءاً من النص أو اسم الزر، حتى إذا لم تتذكره حرفياً.
- يعرض البوت أقرب نتيجة كاملة ويسأل: **هل أنت تبحث عن هذا؟**
- اكتب `نعم` أو اضغط زر التأكيد، ثم أرسل النص الجديد مع Custom Emoji المميز أو معرّفه بين أقواس مربعة.
- التعديل يطابق النص الأصلي كاملاً فقط، حتى لا يغيّر عبارات مشابهة بالخطأ.
- تغيير اسم زر لوحة المفاتيح لا يعطل وظيفته؛ يعيد البوت الاسم الظاهر إلى الاسم الداخلي الأصلي عند الضغط.
- شاشة **النصوص والأزرار المعدلة** تسمح بإلغاء أي تعديل وإرجاع الأصل من دون حذف منتج أو مخزون أو طلب.
- فهرس البحث يستبعد كلمات المرور ومفاتيح API وبيانات التسليم الحساسة، ولا يفهرس رسائل الزبائن الخاصة. النصوص التي لم تظهر بعد تصبح قابلة للبحث بعد فتح شاشتها مرة واحدة من حساب الأدمن.

### المراجعة الذكية للإيموجيات — v7.3

- اختيار إيموجي المنتج يعتمد على اسم الخدمة الأكثر تحديداً في العربية والإنجليزية. لذلك `كاب كات برو 6 شهور (مشترك)` يأخذ CapCut، و`حساب جوجل (جيميل)` يأخذ Gmail، وليس إيموجي كلمة عامة أخرى.
- تعديلات المالك اليدوية محفوظة وتفوز عندما تكون مرتبطة بنفس الخدمة. عند التعارض بين خدمتين داخل الاسم، تفوز الخدمة ذات العبارة الأدق مثل `Google One` و`YouTube Premium` و`Gmail`.
- من شاشة **الإيموجيات المميزة** يوجد زر **مراجعة إيموجيات المنتجات**. يفحص كل المنتجات ويصحح حقول الإيموجي فقط، ويعرض الأسماء غير المعروفة التي تحتاج ربطاً يدوياً.
- عند حفظ ربط خدمة جديد أو حذفه، تُزامن إيموجيات المنتجات الموجودة فوراً، من دون انتظار إعادة تشغيل البوت.
- التطبيق أصبح مركزياً على الرسائل العادية ورسائل HTML والتعليقات على الصور والأزرار. يقرأ صياغة كل سطر ويضيف إيموجي الخدمة أو الإجراء المناسب، ولا يكرر الإيموجي إذا كان السطر يحتوي Custom Emoji مسبقاً.
- المراجعة لا تغيّر اسم المنتج أو السعر أو الوصف أو المخزون أو الطلبات أو المبيعات؛ التحديث محصور في حقول عرض الإيموجي داخل وصف المنتج.

### تثبيت هوية المنتجات والأزرار — v7.4

- Canva وCapCut وGmail وبقية الخدمات المعروفة تستخدم معرّف الخدمة المؤكد، ولا يستطيع ربط قديم غير موثوق أو تعديل عام لنص الزر تبديل هوية المنتج.
- الربط القديم الخاطئ لا يُحذف من قاعدة البيانات؛ يُعزل عن المنتجات المعروفة فقط. أي ربط يحفظه المالك عمداً من شاشة الإصدار الحالي يُعد تغييراً مؤكداً ويمكنه استبدال الافتراضي.
- عند أول تشغيل لهذا الإصدار تُصحح مرة واحدة معرّفات قاموس المالك الأساسية، ومنها المال `5361656830944624968` والحفظ/الصندوق `5366201992970518798`، من دون لمس بيانات المستخدمين أو المنتجات أو المخزون أو الطلبات.
- أزرار لوحة الرد تحتفظ الآن بخريطة بين النص الظاهر والأمر الداخلي. لذلك تبقى أزرار المنتجات والدعم والمحفظة والطلبات والهدايا والقناة والعملة واللغة والأرقام الافتراضية فعالة بعد إزالة الرمز العادي أو تغيير النص من لوحة المالك، وحتى بعد إعادة تشغيل البوت.
- فحص الربط يغطي أزرار Callback الثابتة والديناميكية؛ تغيير الإيموجي أو النص لا يغيّر `callback_data` الخاص بالزر.

### أرخص أسعار الأرقام — v7.5

- يقرأ SMSBower وGrizzlySMS طبقات الأسعار الكاملة عبر `getPricesV2` عند دعمها، ثم يرجع تلقائياً إلى `getPrices` عند عدم دعمها.
- أضيف زر **أرخص الأرقام الآن** داخل كل مزود، ويعرض كل الخدمات المتوفرة مرتبة من الأرخص إلى الأغلى بدلاً من حصر الواجهة بالخدمات المشهورة.
- أسعار الأرقام تظهر وتُثبت وقت الشراء بدقة أربع منازل؛ لذلك يظهر السعر `0.0300$` ولا يتحول إلى `0.03$` أو `0.00$` داخل مسار الشراء والاسترجاع.
- بقي هامش الربح المحفوظ لكل مزود كما هو ولم يُعدّل تلقائياً. سعر البيع = سعر الموقع + هامش الربح؛ ويمكن للمالك ضبط الهامش إلى صفر من لوحة المزود إذا أراد عرض سعر الموقع نفسه.
- يحسب عدد الأرقام المعروض عند أرخص طبقة فقط، فلا يخلط مخزون الطبقات الأعلى سعراً مع المخزون الرخيص.
- أزرار الشراء القديمة المفتوحة قبل التحديث تبقى مقبولة، بينما تستخدم الأزرار الجديدة وحدة `1/10000` دولار لمنع اختلاف السعر بين العرض والتأكيد.

### مزامنة الإيموجيات بين جميع البوتات — v7.6

- قاموس الإيموجيات الذي يحفظه المالك الرئيسي يُنشر عبر شبكة المتاجر ويصل إلى كل بوت عميل خلال دورة المزامنة التالية، بحد أقصى يقارب 30 ثانية.
- عند تشغيل بوت عميل، يجلب القاموس المشترك قبل عرض المنتجات. وإذا كان البوت الرئيسي قيد إعادة النشر يحتفظ البوت بنسخته المحلية ويعيد المحاولة تلقائياً لاحقاً.
- إضافة ربط أو تحديثه أو حذفه من شاشة **الإيموجيات المميزة** ينعكس على جميع بوتات الشبكة، مع بقاء الترجمة العربية والإنجليزية في ربط واحد.
- إذا كان ربط منصة معروفة يستخدم معرّف منصة معروفة أخرى — مثل Canva بمعرّف YouTube — يصحح البوت التعارض إلى هوية المنصة الصحيحة ثم يراجع منتجاتها الموجودة.
- يظل تغيير منصة معروفة إلى معرّف Premium جديد مسموحاً؛ التصحيح التلقائي يعمل فقط عند اكتشاف معرّف معروف تابع بوضوح لخدمة أخرى.
- المزامنة تستخدم إعدادات الإيموجيات فقط، ولا تنقل مفاتيح API أو بيانات المستخدمين أو المخزون أو الطلبات.

## الدفع

- Binance ID: بعد إنشاء الدفع لا يظهر زر تحقق ولا رمز ملاحظة؛ البوت ينتظر من الزبون إرسال `Order ID` مباشرة.
- التحقق يعتمد على `Order ID` + المبلغ + وقت العملية.
- إذا Binance يرفض موقع السيرفر، تنتقل العملية للمراجعة اليدوية بدل مطالبة الزبون بالدفع مرة ثانية.
- شحن المحفظة يقبل مبالغ أقل من 1$ ابتداءً من 0.01$.
- SuperQi: إيصال وموافقة/رفض من الأدمن.
- شحن المحفظة يستخدم نفس طرق الدفع.

## 📱 الأرقام الافتراضية — v7

تم فصل مزودي الأرقام الثلاثة بالكامل عن بعضهم داخل البوت: `SMSBower` و`SMS-MAN` و`GrizzlySMS`.

- للزبون لا تظهر أسماء المواقع الحقيقية؛ تظهر **خدمة 1** و**خدمة 2** و**خدمة 3** بحسب المزودات المهيأة.
- ترتيب الخدمات ديناميكي: الموقع الأكثر إكمالاً للطلبات ثم الأكثر شراءً يصعد إلى **خدمة 1 🔥** تلقائياً.
- إذا كان API لموقع واحد فقط مضافاً، يظهر للزبون موقع واحد فقط.
- إذا لم يكن أي API مضافاً، يختفي زر **📱 شراء رقم افتراضي** بالكامل.
- لكل مزود API مستقل، كاش مستقل، شراء مستقل، حالات مستقلة وربح مستقل. لا يوجد تحويل خفي بين المزودات أثناء الشراء.
- مفتاح GrizzlySMS يُحفظ من زر GrizzlySMS المخصص. وإذا لُصق نص كامل يحتوي اسم أو رابط GrizzlySMS، يتعرف البوت على المزود تلقائياً ولا يرسل المفتاح إلى SMS-MAN.
- لوحة الأدمن → **📱 مواقع الأرقام** تسمح بإضافة/حذف/فحص API لكل موقع وتعديل الربح لكل رقم.
- الربح الافتراضي: **0.15$** لكل موقع، ويمكن ضبطه مثلاً إلى 0.20$ للموقع الأول و0.30$ للثاني.
- تعرض القوائم فقط التطبيقات/الدول التي يرجع الـAPI أنها متوفرة حالياً. قبل الشراء يتم فحص السعر والتوفر مرة ثانية.
- مدة انتظار SMS أصبحت **10 دقائق**. إذا انتهت المدة ولم يصل الكود، يحاول البوت إلغاء الرقم لدى نفس الموقع، وبعد تأكيد الإلغاء يرجع المبلغ إلى محفظة الزبون.
- إذا اختفى الرقم أثناء لحظة الشراء، يعيد البوت تحديث الخيارات ضمن نفس الموقع بدلاً من رفع السعر أو الانتقال لموقع آخر.

### متغيرات Railway الاختيارية

يمكن إدارة مفاتيح API من لوحة الأدمن، أو وضعها كمتغيرات بيئة:

```env
SMSBOWER_API_KEY=
SMSMAN_API_KEY=
GRIZZLYSMS_API_KEY=
GRIZZLYSMS_BASE_URL=https://api.grizzlysms.com/stubs/handler_api.php
VIRTUAL_NUMBERS_POLL_INTERVAL_MS=7000
```

إعداد الربح محفوظ داخل قاعدة البيانات لكل موقع على حدة، لذلك لا يحتاج Variable في Railway.

### إدخال مفتاح API بأمان

تقبل شاشة إعداد المزود قيمة المفتاح وحدها، أو `API_KEY=...`، أو رابط API كاملاً. تُزال علامات الاقتباس والمسافات والمحارف الخفية قبل الفحص، ثم يختبر البوت `getBalance` لدى الموقع المختار. لا يُحفظ المفتاح إذا رفضه الموقع فعلياً، ولا يُعرض بعد الحفظ.
