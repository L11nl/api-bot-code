# CD Store v11.8

نسخة الشبكة التي تفصل بين **رصيد المحفظة** و**عملة طريقة الدفع** وتحوّل تسوية الديون بين أصحاب البوتات إلى USD عبر Binance.

## القواعد المالية

- رصيد كل مستخدم داخل أي بوت هو **USD فقط**.
- أسعار المنتجات تبقى **USD**.
- طريقة الدفع نفسها تحدد عملة التحويل: `USD` أو `IQD` أو `EGP`.
- عند الدفع بطريقة محلية، المبلغ المحلي يتحول إلى USD حسب سعر 1$ المحفوظ في طريقة الدفع، ثم يُضاف رصيد USD أو يكمّل قيمة الطلب.
- داخل المحفظة والشراء تظهر الطرق بهذا الترتيب:
  1. دفع بالدولار
  2. دفع بالدينار العراقي
  3. دفع بالجنيه المصري
- Binance يبقى USDT/USD دائماً.

## طرق الدفع المشتركة

- الطرق العادية مثل Vodafone Cash أو زين كاش يمكن مشاركتها بين كل البوتات.
- كل طريقة مشتركة تحتفظ بصاحبها الحقيقي، العملة، رقم التحويل، سعر 1$، والحد الأدنى.
- الموافقة على الإيصال تذهب إلى **صاحب طريقة الدفع الحقيقي** حتى لو الزبون موجود في بوت شريك آخر.
- بعد الموافقة، البوت الذي فيه الزبون يكمل العملية ويشحن محفظته بالدولار أو يسلم الطلب.
- أدمن البوت الذي تمت فيه العملية يستلم إشعار نجاح فيه الزبون ومن وافق (`@username` إن موجود، وإلا Telegram ID).
- المبلغ الذي دخل عند صاحب طريقة الدفع نيابة عن متجر آخر يُسجل في Ledger الشبكة بالدولار، حتى تبقى الحسابات عادلة.

### مثال

زبون داخل بوت أحمد استخدم طريقة دفع عراقية تخص نبيل بقيمة تعادل 1$:

1. الإيصال يروح إلى نبيل.
2. نبيل يوافق.
3. محفظة الزبون في بوت أحمد تُشحن 1 USD.
4. أحمد يستلم إشعار أن نبيل وافق.
5. الحسابات تسجل أن نبيل استلم 1$ نيابة عن أحمد، لذلك يظهر الالتزام الصحيح بين الطرفين.

## Binance الأساسي

- Binance الخاص بكل بوت يبقى خاصاً به.
- API Key وSecret لا يتم إرسالهما إلى باقي البوتات أو إلى شبكة المنتجات.
- الشبكة تعرف فقط Binance ID وحالة أن Binance جاهز للتسوية.

## الديون بين أصحاب البوتات

- كل الديون والتسويات بين أصحاب البوتات هي **USD فقط**.
- إذا نبيل يطلب أحمد 5$، أحمد يرى المبلغ وBinance ID الخاص بنبيل.
- أحمد يحول 5 USDT ثم يرسل Order ID داخل البوت.
- بوت نبيل يتحقق تلقائياً من Order ID باستخدام Binance API الخاص بنبيل.
- عند نجاح التحقق يُغلق مبلغ التسوية تلقائياً ويصل إشعار للطرفين.
- لا يمكن استخدام نفس Order ID لتسوية دين مرتين.
- إذا Binance API رجع `REGION_RESTRICTED`، لا يتم إغلاق الدين؛ لا توجد محاولة لتجاوز قيد Binance الجغرافي.

## حدود الديون

- يبدأ تذكير الدين من **15$**.
- التذكير كل 30 دقيقة طالما الدين مفتوح ولم تبدأ له تسوية.
- عند وصول الالتزامات إلى **40$** تتوقف المبيعات والشحنات الجديدة مؤقتاً، وتعود بعد نجاح التسوية.

## عمولة ومخزون الشبكة

- كل قطعة مخزون لها صاحب حقيقي.
- مخزون صاحب البوت نفسه له الأولوية داخل بوت ذلك الصاحب، ثم مخزون الشركاء.
- إذا باع متجر مخزون شريك آخر، عمولة البائع الافتراضية 10% وحق صاحب المخزون 90%.
- كل تسليم له `DLV-...` ويمكن للإدارة البحث به أو برقم الطلب ومعرفة صاحب المخزون الحقيقي.

## النشر

كل البوتات في الشبكة، Master وClients، يجب تحديثها إلى نفس v11.8 لأن هذه النسخة تضيف أعمدة وAPI خاصة بالموافقة والتسوية.

لا تحتاج Variables جديدة. الجداول والأعمدة الجديدة تُنشأ تلقائياً عند أول تشغيل.

بعد النشر شغّل:

```bash
npm run check
```

وفي Railway راقب Logs وتأكد أن كل Client يطبع Schema الخاص به، وليس `public`.


## v11.9 — اختيار عملة الدفع بواسطة الزبون

- الزبون يختار عملة الدفع المحلية بنفسه: **جنيه مصري (EGP)** أو **دينار عراقي (IQD)**.
- الاختيار محفوظ لكل مستخدم ويمكن تغييره لاحقاً من زر **💱 العملة** أو من المحفظة.
- أسعار المنتجات ورصيد المحفظة تبقى **USD فقط**.
- **Binance يبقى USDT فقط** ولا يعرض أي تحويل إلى EGP أو IQD.
- إذا اختار المستخدم EGP تظهر Binance + طرق EGP فقط. وإذا اختار IQD تظهر Binance + طرق IQD فقط.
- طرق صاحب البوت لنفس العملة لها الأولوية داخل بوتّه. إذا لم توجد، يستخدم النظام مزوداً احتياطياً من الشبكة؛ للـClient يفضّل طرق الـMaster لنفس العملة، وإذا لم توجد يختار مزوداً شبكياً متاحاً (مثلاً أحمد لطرق EGP).
- الأزرار القديمة محمية: لو غيّر الزبون العملة ثم ضغط زر دفع قديم من العملة الثانية، يرفضه البوت ويطلب اختيار العملة الصحيحة.
