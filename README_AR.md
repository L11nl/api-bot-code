# CD Store — النسخة المبسطة v6

نسخة مرتبة لتكون سهلة جداً للمستخدم والأدمن، مع الحفاظ على الدفع والطلبات والدعم.

## واجهة المستخدم

- عند `/start` تظهر المنتجات مباشرة بعد رسالة الترحيب.
- المنتج المتوفر يظهر بزر أخضر.
- المنتج الذي مخزونه صفر يظهر بزر أحمر.
- أزرار الشحن والدفع تستخدم نمط Telegram الأزرق `primary`.
- اللغة العربية والإنجليزية موجودتان، ومحتوى المنتجات الذي يكتبه الأدمن بالعربي يترجم للإنجليزية تلقائياً.
- الإعلانات وردود الدعم المكتوبة بالعربي تترجم تلقائياً للمستخدم الذي اختار English.

## لوحة الأدمن

لوحة `/admin` تظهر فقط للأرقام الموجودة داخل `ADMIN_IDS`، وأمر `/admin` يضاف لقائمة أوامر Telegram للأدمن فقط.

أهم الأقسام:

- إضافة منتج.
- المنتجات وإدارتها.
- الطلبات ودفعات SuperQi.
- إدارة المستخدمين والرصيد.
- الدعم والإعلانات.
- الإحالات والقناة.
- إعدادات المتجر.
- زر `الإشعارات` داخل لوحة الأدمن: تشغيل/إيقاف الإشعارات التلقائية للمنتجات والمخزون.

## إضافة منتج

يوجد مكان واحد واضح: `➕ إضافة منتج`.

أول سؤال:

**ما نوع المنتج؟**

1. `كود`
2. `إيميل وباسورد`
3. `منتج حر`

بعدها يطلب فقط:

1. الاسم بالعربي.
2. السعر.
3. الوصف بالعربي.
4. الضمان بالعربي.
5. الصورة.
6. المخزون.

لا يطلب منك كتابة الإنجليزية؛ الاسم والوصف والضمان تترجم تلقائياً.

### المخزون

**كود** — كل كود بسطر:

```text
ABC-123
XYZ-456
```

**إيميل وباسورد** — كل حساب بسطر:

```text
email@example.com|password
```

**منتج حر** — كل سطر قطعة مستقلة، ويمكن أن يكون كتابة أو رابطاً أو بيانات أو أي نص:

```text
أي محتوى تريد تسليمه
```

## Telegram Premium Custom Emoji

إذا كتب الأدمن اسم المنتج وداخله Custom Emoji من Telegram Premium، يخزن البوت `custom_emoji_id` تلقائياً. ويمكن أيضاً كتابة ID الإيموجي بين أقواس مربعة مثل `[5221980268230882832] اسم المنتج`؛ الأقواس والرقم لا يظهران للزبون، وإنما يستخدم الـID كـCustom Emoji. إذا لم يسمح Telegram باستخدام الـCustom Emoji يوجد fallback حتى لا تتعطل قائمة المنتجات.

## الدفع

- Binance ID: بعد إنشاء الدفع لا يظهر زر تحقق ولا رمز ملاحظة؛ البوت ينتظر من الزبون إرسال `Order ID` مباشرة.
- التحقق يعتمد على `Order ID` + المبلغ + وقت العملية.
- إذا Binance يرفض موقع السيرفر، تنتقل العملية للمراجعة اليدوية بدل مطالبة الزبون بالدفع مرة ثانية.
- شحن المحفظة يقبل مبالغ أقل من 1$ ابتداءً من 0.01$.
- SuperQi: إيصال وموافقة/رفض من الأدمن.
- شحن المحفظة يستخدم نفس طرق الدفع.

## 📱 الأرقام الافتراضية — v7

تم فصل موقعي الأرقام بالكامل عن بعضهما داخل البوت:

- للزبون لا تظهر أسماء المواقع الحقيقية؛ يظهر فقط **خدمة 1 🔥** و **خدمة 2**.
- ترتيب الخدمات ديناميكي: الموقع الأكثر إكمالاً للطلبات ثم الأكثر شراءً يصعد إلى **خدمة 1 🔥** تلقائياً.
- إذا كان API لموقع واحد فقط مضافاً، يظهر للزبون موقع واحد فقط.
- إذا لم يكن أي API مضافاً، يختفي زر **📱 شراء رقم افتراضي** بالكامل.
- لكل موقع API مستقل، كاش مستقل، شراء مستقل، حالات مستقلة وربح مستقل. لا يوجد تحويل خفي بين الموقعين أثناء الشراء.
- لوحة الأدمن → **📱 مواقع الأرقام** تسمح بإضافة/حذف/فحص API لكل موقع وتعديل الربح لكل رقم.
- الربح الافتراضي: **0.15$** لكل موقع، ويمكن ضبطه مثلاً إلى 0.20$ للموقع الأول و0.30$ للثاني.
- تعرض القوائم فقط التطبيقات/الدول التي يرجع الـAPI أنها متوفرة حالياً. قبل الشراء يتم فحص السعر والتوفر مرة ثانية.
- مدة انتظار SMS أصبحت **10 دقائق**. إذا انتهت المدة ولم يصل الكود، يحاول البوت إلغاء الرقم لدى نفس الموقع، وبعد تأكيد الإلغاء يرجع المبلغ إلى محفظة الزبون.
- إذا اختفى الرقم أثناء لحظة الشراء، يعيد البوت تحديث الخيارات ضمن نفس الموقع بدلاً من رفع السعر أو الانتقال لموقع آخر.

### متغيرات Railway الاختيارية

يمكن إدارة مفاتيح API من لوحة الأدمن، أو وضعها كمتغيرات بيئة:

```env
SMSBOWER_API_KEY=
SMSMAN_API_KEY=
VIRTUAL_NUMBERS_POLL_INTERVAL_MS=7000
```

إعداد الربح محفوظ داخل قاعدة البيانات لكل موقع على حدة، لذلك لا يحتاج Variable في Railway.
