# CD Store v9 — تفعيل بوت شريك من داخل البوت

هذه النسخة تكمل نظام **Master / Client** وتبسط إنشاء بوتات الأصدقاء. المالك الرئيسي لا يحتاج أن ينشئ PostgreSQL جديداً لكل بوت شريك ولا يكتب إعدادات الشبكة بيده.

## الفكرة الجديدة في v9

من البوت الرئيسي:

`/admin → API والشركاء → تفعيل بوت صديق`

البوت يسأل فقط:

1. اسم البوت/المتجر.
2. Telegram ID الرقمي لصاحب البوت.
3. BOT TOKEN للبوت الجديد من BotFather. رسالة التوكن تُحذف بعد قراءتها ولا يُخزن التوكن في قاعدة البيانات.
4. عملة الحساب: IQD أو EGP أو USD.

بعدها يولّد البوت بلوك Variables كامل وجاهز للنسخ إلى Railway، ويظهر أيضاً أزرار **نسخ الإعدادات** باستخدام زر النسخ الرسمي في Telegram.

## قاعدة البيانات التلقائية

لا تنشئ PostgreSQL جديداً لكل صديق.

كل بوت Client يستخدم نفس خدمة PostgreSQL الموجودة في **نفس مشروع Railway**، لكن يحصل على **Schema مستقل** مثل:

```text
client_c57a89650f9b
```

عند أول تشغيل، البوت ينشئ الـSchema والجداول تلقائياً. بيانات مستخدمي نبيل2 ومحفظتهم وطلباتهم وإعداداتهم المحلية تبقى منفصلة عن بيانات البوت الرئيسي وعن باقي الشركاء.

السطر الذي يولده البوت تلقائياً هو:

```env
DATABASE_URL=${{Postgres.DATABASE_URL}}
```

وهذا Reference Variable رسمي من Railway لخدمة PostgreSQL داخل نفس المشروع. يجب أن يكون اسم خدمة قاعدة البيانات في Railway هو `Postgres`.

## ماذا أفعل بعد أن يولّد البوت الإعدادات؟

1. افتح **نفس مشروع Railway** الذي فيه البوت الرئيسي وخدمة `Postgres`.
2. أنشئ Service جديد للبوت الشريك وارفع/اربط نفس ملفات v9.
3. افتح `Variables → Raw Editor`.
4. الصق البلوك الذي أعطاك إياه البوت الرئيسي.
5. Deploy.

انتهى. لا تضيف Database جديدة ولا تنشئ جداول يدوياً.

مثال للبلوك الذي يولده البوت:

```env
BOT_TOKEN=TOKEN_OF_PARTNER_BOT
ADMIN_IDS=123456789
DATABASE_URL=${{Postgres.DATABASE_URL}}
DATABASE_SCHEMA=client_c57a89650f9b
NETWORK_ROLE=client
NETWORK_API_URL=https://YOUR-MASTER.up.railway.app
NETWORK_API_KEY=net_...
NETWORK_SHOP_ID=shop-c57a89650f9b
NETWORK_SHOP_NAME=نبيل2
NETWORK_SETTLEMENT_CURRENCY=IQD
```

`NETWORK_API_URL` يقبل الرابط حتى لو نُسخ بدون `https://`؛ v9 يضيف `https://` تلقائياً عند الحاجة.

## البوت الرئيسي Master

يبقى إعداد البوت الرئيسي كما هو. إذا Railway وفر `RAILWAY_PUBLIC_DOMAIN` للبوت الرئيسي، الكود يستطيع استخدامه تلقائياً. ويمكن إبقاء `NETWORK_PUBLIC_URL` صراحةً أيضاً.

```env
BOT_TOKEN=...
ADMIN_IDS=...
DATABASE_URL=${{Postgres.DATABASE_URL}}
DATABASE_SCHEMA=public
NETWORK_ROLE=master
NETWORK_PUBLIC_URL=https://YOUR-MASTER.up.railway.app
NETWORK_OWNER_NAME=نبيل
```

## المنتجات والدفع والشبكة

كل ميزات v8 باقية:

- المنتجات والمخزون المشترك مصدرهما الـMaster.
- أي منتج يضاف من البوت الرئيسي يظهر في بوتات الشركاء.
- منتج الشريك يذهب للـMaster ثم يظهر للجميع.
- لا يمكن بيع آخر كود مرتين من بوتين مختلفين.
- الشريك يستطيع إضافة Binance الخاص به وطرق دفعه المحلية.
- إذا لا يملك Binance/SuperQi محلياً، تظهر طرق الدفع الرئيسية كـfallback.
- إذا استُخدمت طريقة دفع رئيسية في بوت شريك، تسجل المديونية بين الشريك والمالك الرئيسي.
- دفع الفرق من المحفظة يعمل: إذا المنتج 2$ والرصيد 1$، المطلوب خارجياً 1$ فقط.
- كل قطعة مسلمة تحصل على `DLV-...` ثابت ويمكن استرجاعها لاحقاً بدون صرف قطعة جديدة.

## أمان BOT TOKEN

عند خطوة إدخال BOT TOKEN:

- البوت يتحقق من صيغة التوكن.
- يحذف رسالة الأدمن بعد قراءتها قدر الإمكان.
- يحتفظ به مؤقتاً في الذاكرة فقط خلال معالج الإعداد.
- لا يكتبه داخل جدول الشركاء.
- يظهر في رسالة الإعداد النهائية لأنك طلبت بلوك جاهز للنسخ إلى Railway، لذلك لا تشارك هذه الرسالة مع غير صاحب البوت.

## إذا أردت لكل صديق PostgreSQL منفصل فعلياً

v9 افتراضياً يستخدم **Schema منفصل داخل Postgres الرئيسي** لأنه أبسط وأسرع ولا يحتاج إنشاء Database Service لكل شريك. إذا أردت لاحقاً قاعدة PostgreSQL مستقلة فعلياً لكل صديق في مشروع Railway مستقل، هذا يحتاج إما Railway Template أو Railway Public API/CLI وصلاحية Railway إضافية.
